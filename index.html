最终交付：一台物理上远在别处的小台式机（Ryzen 7 8845HS / 32G / 1TB NVMe），现在是 Ubuntu 24.04.5 LTS 服务器——WiFi 自动联网、SSH 密钥免密、开机自动向管理端上报 IP，同时 Windows 11 完好保留构成 GRUB 双系统。操作者全程只用了一台 MacBook 和一杯茶。

背景与约束

目标机器是一台放在别处的小台式机，原装 Windows 11 专业版。需求：装 Linux 做个人服务器，保留 Windows 双系统，且全程远程操作——人在 A 处，机器在 B 处，中间只有一张 office WiFi。初始可用条件只有一个：RDP 远程桌面能连上它。

这个约束决定了整个战役的技术形态：装机必经的"重启 + 引导介质"环节，是远程操作的天然断层。所有方案设计都围绕如何跨越这个断层展开。

战役时间线

🏗️ 打地基：RDP 里开 SSH

Day 1 晚

在 RDP 会话里以管理员 PowerShell 安装 OpenSSH Server、配防火墙、写入管理端公钥。期间踩了两个小坑（公钥行被吞空格导致拒登、PowerShell 编码乱码），全部快速排除。从此 RDP 退役，SSH 成为唯一通道。

📐 摸底与规划：选定 autoinstall 无人值守方案

Day 1 晚

SSH 进去盘点：UEFI+GPT、单盘单 C 区、WiFi 联网（Intel AX200，Linux 原生支持）。用户确认"保留 Windows 双系统 + 静态 IP + WiFi"。方案定型：Windows 侧缩盘 600GB → QEMU 直通物理盘引导 Ubuntu ISO → autoinstall 应答盘全自动安装，避开"装机必重启"断层。

📦 下载 3.8GB ISO：网络被掐到 500KB/s

Day 1 深夜（约 2 小时）

试遍国内 4 大镜像、代理、10 线程并发——统统 ~500KB/s，是办公室 WiFi 的链路上限。最终用 10 并发分块 + SHA256 校验的持久 SSH 会话完成下载。教训：先测链路上限再选方案，别跟物理规律较劲。

🚀 第一轮点火：连环三坑

Day 2

QEMU 启动脚本接连修掉三个坑（见下文深坑 ③④），VM 跑起来后，subiquity 安装器每轮都在不同位置报错——正式进入"一轮修一个、报错往后挪"的攻坚节奏。

💥 第 5-6 轮：GPT 分区表被清空（全程最大事故）

Day 2

autoinstall 存储配置补上 ptable: gpt 后，curtin 的磁盘处理器把"创建新分区表"理解成了 sgdisk --zap-all——整张 GPT 分区表元数据被清零。万幸：只清了表，没碰数据区，Windows 靠内存里的分区表还活着。

🚑 GPT 抢险：Python 手写分区表

Day 2

趁 Windows 内存表还活着，导出全部 4 个分区的精确偏移/大小/类型 GUID/分区 GUID/磁盘 GUID，在 Mac 上用 Python 重建完整 GPT 结构（保护 MBR + 主备头 + CRC32 条目数组），PowerShell 原位写回。rescan 后分区带原 GUID 回归，重启验证通过，数据零损失。

🔧 第 8-11 轮：curtin 三连 + 缓存战争

Day 2 深夜

偏移量被忽略 → Windows 侧直接建好分区让它 preserve；分区号被 Windows 重排 → 逐轮校准；wpasupplicant 没装进 target → chroot 补装。宿主 Windows 与 guest 双缓存的读写冲突贯穿始终，靠"关键动作前重启宿主清缓存"续命。

💀 第 12 轮：装好了，但机器"消失"了

Day 2 深夜

系统完整写入、GRUB 装好、用户建好——重启后 Ubuntu 起来了，WiFi 却怎么都连不上，机器成了"活着但够不着"的黑盒，连 ping 都不响应。战斗暂停，等用户物理按电源键。

🔍 真相：两个叠加的 WiFi 根因

Day 3

通过诊断 shell 读真实日志：① netplan 的 networkd 后端不支持 match: 通配符配 WiFi（每次开机 netplan apply 都 exit 78，WiFi 从未被配置）；② target 里根本没装 wpasupplicant 包。两个都修掉后，iw dev wlp2s0 link 显示 SSID='FSWLAN' 关联成功、DHCP 拿到 172.26.7.128。

📡 电话回家 + 最终验收

Day 3

机器落在未知网段 172.26.x，管理端在 172.28.x。给 target 部署 phonehome 服务：开机后自动 curl http://172.28.0.216:8000/ip-xxx 向管理端报告自己的 IP。日志亮起的瞬间，SSH 直连成功——hostname 改为 ubuntu-server、GRUB 补上 Windows 菜单项、全项验收通过。战役结束。

六大深坑复盘

① Windows OpenSSH 公钥拒登入门坑

administrators 用户的公钥必须放 C:\ProgramData\ssh\administrators_authorized_keys（不是用户家目录），且 ACL 只允许 SYSTEM + Administrators。另外粘贴公钥时行内空格被吞（...RmpBxzhangwch@...）整行作废——密钥类内容务必写完后 readback 校验。

② SSH 会话断开 = 子进程全灭架构坑

Windows sshd 会随会话终止清理整棵进程树，Start-Process 分离的进程也逃不掉。长任务（下载、QEMU）必须二选一：① 计划任务 + /RU /RP 存凭据方式启动（/RL HIGHEST）；② 保持 SSH 会话存活的持久会话内前台运行。另外：非交互会话里 VNC 键盘映射会被拒（QEMU 加 -vnc 直接启动失败）。

③ PowerShell 与 QEMU 的三连暗箭细节坑

Start-Process -ArgumentList 数组不给含空格的元素加引号（C:\Program Files\... 被从空格劈开）；QEMU 11.1 的 -bios 加载 OVMF 失败（改用 -drive if=pflash 对）；sendkey 组合键必须单条命令（sendkey alt-sysrq-o，拆开发等于没按）。

④ GPT 被清空：autoinstall 双标志缺一不可事故级

给已有系统的盘写自定义 storage，disk 条目必须同时有 ptable: gpt（否则 curtin 走不进分区分支）和 preserve: true（否则磁盘处理器直接 zap 全表）。只写前者 = 触发清盘。抢险要点：趁内存表活着导出精确布局 → 重建 GPT 结构（CRC32 用 zlib）→ 单 OS 侧原位写回 → rescan 验证。数据区永远没被碰到。

⑤ 宿主/guest 双缓存战争架构坑

QEMU 直通 + Windows 宿主同盘并行：guest 写入经宿主 writeback 缓存不即时落盘；cache=directsync 反而让 guest 读到全零；Windows 改写分区表后 guest 读到新旧混合的脏页。对策：关键节点前重启宿主清缓存；跨系统对分区永远以 GUID/偏移为准而非序号（Windows 按偏移重排分区号，Linux 按 GPT 条目序，两边对不上）。

⑥ WiFi 双根因：netplan 不支持 match + wpasupplicant 缺失隐蔽级

两个独立问题叠加，表面症状完全一样（WiFi 不上线），必须看日志才能拆开：① netplan 的 networkd 后端不支持 wifi 用 match: 通配符，只能写死接口名（wlp2s0，违反就 exit 78 静默失败）；② target 缺 wpasupplicant 包（curthooks 只装了 GRUB 系列没装它）。以及最后的大坑：机器落在未知网段——解法是给 target 部署 phonehome 服务，开机自动向管理端上报 IP。

方法论：远程装机的正确姿势

  • SSH 先行：RDP 只用来开一次 SSH，之后所有操作命令化、可审计、可重放
  • 长任务用计划任务存凭据启动，或者接受"会话保活"模式——绝不依赖 Start-Process 分离
  • 下载前先测链路上限，用多并发分块 + 强校验（SHA256），校验不过不进下一步
  • autoinstall 双标志：已有系统的盘 = ptable: gpt + preserve: true 同时写；分区直接在宿主侧建好让安装器 preserve，绕开 curtin 的偏移计算
  • 分区身份用 GUID 不用序号——Windows 和 Linux 的分区编号规则不同且会变
  • 跨 OS 同盘操作，写后必刷盘、读前怀疑缓存；大节点之间重启宿主清缓存是廉价保险
  • netplan WiFi：networkd 后端只认接口名，并且确认 wpasupplicant 包真的装进去了
  • phonehome 机制：给无屏设备部署开机报 IP 的服务，管理端一个 HTTP 日志就能找回它——这是整个战役最值钱的设计
  • 出黑盒先读日志再动手：诊断 shell（故意秒失败的 seed 是免费入场券）+ 真实 syslog，比任何猜测都值钱

故意秒失败的 seed（免费诊断 shell 入场券）

# storage 配置故意少一个 device 键
- {id: root-part, type: partition, number: 4, ...}   # ← 没有 device:
# subiquity 在 convert 阶段立即抛错，零写盘，
# "Press enter to start a shell" = 拿到 live 环境 root shell

Python 手写 GPT（抢险核心）

import struct, zlib, uuid
# GUID 转 GPT 混合端序：uuid.UUID(g).bytes_le
# 主头: "EFI PART" + rev 1.0 + 92字节头 + CRC32(头) + 备份LBA + 磁盘GUID
#       + 条目数组LBA + 128条目×128B + CRC32(条目)
# 写回: LBA0(PMBR) LBA1(主头) LBA2-33(条目) 尾部(备份条目+头)

phonehome（无屏设备找回）

# target 侧 systemd oneshot，开机后 12×10s 窗口内上报所有全局 IP
ip -4 -o addr show scope global | while read _ addr _; do
  wget -qO- "http://<管理端>:8000/ip-${addr%/*}"
done
# 管理端只需一个 http.server，日志里的 GET 路径就是设备 IP

netplan WiFi 正确姿势（networkd 后端）

network:
  version: 2
  wifis:
    wlp2s0:                    # ✅ 显式接口名（match: ❌ 不支持）
      access-points:
        "SSID-A": {password: "..."}
      dhcp4: true
